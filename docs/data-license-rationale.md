# Data License Rationale — IX pillar live feeds

> **Status:** posture approved by Aden 2026-05-23 ("aggregate-only + document").
> **Companion:** `docs/ix-coverage-matrix.md` (the per-source coverage matrix,
> regenerated by `scripts/ix-coverage-audit.mjs`), `docs/data-trust-audit.md`.
> **Why this exists:** the 2026-05-23 independent 3-agent source sweep found that
> most utility hosting-capacity / interconnection feeds carry "viewer-only /
> unknown" license terms. Tractova is a paid product, so we need a written,
> defensible posture — not an assumption — for redistributing data derived from
> these feeds.

## The posture (one sentence)

**We ingest and republish only per-utility AGGREGATES (counts, percentages,
capacity sums, max, size-bucketed site counts) — never the raw source rows or a
copy of the underlying dataset — and we attribute + link back to each source.**

## Why that is defensible

1. **Facts aren't copyrightable.** Per *Feist v. Rural Telephone* (US), raw
   factual data (a feeder's hosting-capacity MW, a project's queue status) is not
   protected expression. What can be protected is a *creative selection/arrangement*
   (i.e. the dataset as a compiled work). We do not copy the dataset — we compute
   derived statistics from it.
2. **We store aggregates, not the dataset.** Verifiable in code:
   - `hosting_capacity_data` stores per-utility rollups (`total_cells`,
     `cells_with_capacity`, `pct_with_capacity`, `max_avail_mw`,
     `sites_by_threshold`) recomputed server-side each refresh — NOT the
     thousands/millions of raw grid cells. See `api/scrapers/_refresh-hosting-capacity.js`
     (`buildRow()`), which never persists individual features.
   - `ix_queue_data` stores per-utility counts + MW sums (`projects_in_queue`,
     `mw_pending`, `completed_projects`, `completed_mw`) — NOT the per-project
     rows. See the state scrapers in `api/scrapers/_refresh-*-dg.js`.
3. **Attribution + link-back.** Every row carries `data_source` + `data_source_url`;
   the UI surfaces the source label and links to the originating utility/agency.
4. **Transformative use.** We present grid context as one signal inside a
   multi-factor feasibility score, not as a substitute for the utility's tool.

## What we will NOT do

- **Never ingest a source whose terms explicitly prohibit it.** Confirmed
  `prohibited`: `californiadgstats.ca.gov` (terms bar extraction/redistribution
  beyond the NEM program) and IL `Illinois Shines` XLSX (bars commercial
  redistribution). These stay out — even though the data is rich. (No fabrication,
  no quiet scraping around a license — see `feedback_no_fabricated_data`.)
- **Never store/republish a raw copy** of any `unknown`-license dataset. Aggregate
  on ingest, discard the raw pull.
- **Never claim a source endorses or partners with us.**

## Per-source license classification

License tiers: **open** (explicit commercial-reuse OK) · **gov** (government /
regulator-mandated public filing — public-record footing) · **unknown** (utility
"viewer-only / informational" disclaimer, no explicit grant or ban — covered by
the aggregate-only rationale above) · **prohibited** (terms forbid it — excluded).

## Review cadence

Re-confirm `prohibited` exclusions and spot-check `unknown` disclaimer wording at
each quarterly data-trust audit (`docs/data-trust-audit.md`). If a utility adds an
explicit ban, demote that feed the same way CO Xcel was demoted 2026-05-23.
